# 基于双视觉与陀螺仪闭环控制的智能循迹车作品设计

> 设计依据：当前“7.6终极版”工程，主配置为 `DebugRingFastLimit2`。文中参数为软件目标值，不等同于实测值。用户反馈本版为当前实车成绩最快版本，尚未提供具体完赛时间。

## 一、作品概述

本作品是一套以 STM32H743VIT6 为主控制器的自主循迹智能车。系统使用 OpenMV H7 Plus 完成赛道边界识别、环岛识别及终点标记检测，使用亚博 K230 完成红色障碍检测，并通过编码器和 ICM42688 陀螺仪反馈实现轮速、转弯角速度与累计转角控制。

车辆具备普通赛道循迹、环岛通行、红色障碍左侧绕行、第三次经过终点后延时停车，以及逐飞无线串口调试等功能。设计以保留现有整车控制架构、减少视觉额外计算、保证控制任务连续执行为原则。

## 二、总体方案

系统采用视觉感知与车辆运动控制分工的方案。两块视觉模块负责提供环境信息，H743 统一处理运动状态切换和执行器输出。

| 模块 | 主要职责 |
|---|---|
| STM32H743VIT6 | 接收视觉信息、调度任务、轮速控制、舵机控制、故障保护 |
| OpenMV H7 Plus | 普通寻迹、环岛视觉状态、黑色终点标记检测 |
| 亚博 K230 | 统计红色像素、输出一次性绕障触发、显示检测框 |
| ICM42688 | 测量车身角速度，为转弯闭环和累计转角提供反馈 |
| 左右轮编码器 | 测量轮速及轮转量，为速度闭环和绕障行程提供反馈 |
| 转向舵机、后轮电机 | 分别执行转向和驱动指令 |
| 逐飞无线串口 | 回传状态与曲线，提供启停、参数和诊断交互 |

信息传递关系为：OpenMV 经专用串口向 H743 发送路线和元素状态；K230 经独立串口发送红色事件命令；H743 结合陀螺仪、编码器反馈控制车辆，并向无线链路输出诊断信息。

无线链路不参与普通循迹的必要保活。电脑无线断连后，车辆仍按本地控制逻辑运行；视觉控制通信和传感器故障由原有保护机制处理。

## 三、普通赛道识别与循迹

### 3.1 图像处理

OpenMV 使用 320×120 图像，内部以 80×60 网格进行灰度与边界分析。通过已有的阈值、边界与路线处理流程提取可行驶路线，计算车辆相对路线的横向偏差，并将控制相关结果发送给主控。

普通循迹结合位置 PD 与自适应预瞄。位置反馈用于修正当前偏差，预瞄用于提前响应前方路线变化，降低仅依赖近处偏差造成的转向滞后。当前预瞄最大增益为 0.45，预瞄输出限幅为 120，二者是算法内部参数，不能直接解释为机械转角。

系统保留现有单边边界恢复与宽度缓存机制。生产相机包必须包含既有 `ring_width_calibration.json` 标定文件，用于相关边界和环岛流程；该文件不能在制作本地安装包时遗漏。

### 3.2 运动控制

H743 根据路线误差控制舵机，结合转向状态协调左右后轮目标速度，并利用编码器反馈执行轮速 PI 控制。外轮目标并不意味着左右轮始终保持相同速度。

当前主档普通直道目标为 7.6 圈/秒，普通弯道外轮目标为 5.1 圈/秒。直道启动满足原有门控条件后采用快速提速逻辑，同时保留电机输出边界、编码器检查和原有故障保护。

## 四、环岛识别与陀螺仪控制

环岛识别沿用现有 OpenMV 元素判断流程。视觉识别到环岛后，主控进入专用环岛控制过程；不使用阻塞延时等待动作结束。

| 阶段 | 执行方式 |
|---|---|
| 识别后直行 | 舵机回中，按设定轮速基准前进 700 ms |
| 入环 | 按环岛方向执行角速度闭环转向 |
| 绕环 | 相机确认入环后建立计角起点，持续角速度闭环 |
| 出环触发 | 沿本次绕环方向净累计转角达到 280° |
| 固定驶出 | 舵机回中，软件输出到中位后保持直行 300 ms |
| 恢复寻迹 | 连续收到 3 帧新鲜有效普通路线后交还普通循迹 |

入环与绕环外轮目标均为 7.6 圈/秒，目标车身角速度为 282°/秒，左右环岛采用镜像方向。转向命令相对舵机中位的偏转倍率为 1.875，并受原舵机输出上下限约束；该倍率不代表前轮机械转角也增加相同倍数。

累计角度采用有方向的净转角，不累加左右摆动的绝对值。角速度目标决定转弯过程的控制方向与强度，累计角度门限决定何时进入出环阶段，两者职责不同。

出环阶段轮速基准为 5.28 圈/秒。固定驶出结束后若未找到普通路线，保持回中并沿用原减速续行流程，最多再续行 3 秒，超时停车。系统保留入环、绕环和传感器异常等保护。

## 五、红色障碍检测与固定左侧绕行

### 5.1 红色检测

K230 使用 CanMV MicroPython，图像分辨率为 320×120，总像素数为 38400。程序按照 LAB 红色阈值统计实际红色像素数量，而非使用检测框面积代替红色面积。

触发条件为红色像素占比严格大于 4%，即：

```text
红色像素数量 > 38400 × 4% = 1536
```

达到条件时，经 UART 发送单字节 `R`。同一次连续满足条件的红色事件只发送一次；检测结果回落到门限以下后，才允许下一次事件触发。屏幕上未达到触发门限时显示蓝色检测框，达到门限时显示绿色检测框。

### 5.2 固定绕行路线

H743 接收到触发后进入独立绕障状态，暂时暂停普通寻迹对运动输出的控制。绕障期间忽略重复触发，继续复用原有电机控制与传感器反馈。

| 顺序 | 动作 | 完成依据 |
|---|---|---|
| 1 | 左转驶离原方向 | 陀螺仪相对转角 30° |
| 2 | 左前斜行 | 左右轮平均前进 0.25 圈 |
| 3 | 右转恢复初始朝向 | 陀螺仪相对转角 30° |
| 4 | 右转驶回赛道方向 | 陀螺仪相对转角 30° |
| 5 | 右前斜行 | 左右轮平均前进 0.25 圈 |
| 6 | 左转恢复初始朝向 | 陀螺仪相对转角 30° |

原路线中独立的“向前绕过障碍”阶段保留配置，但当前运行时跳过。

当前绕障转弯外轮目标复用普通弯道参数，为 5.1 圈/秒；斜行目标为 5.6 圈/秒。转弯目标角速度为 60°/秒。轮转量不是车身位移，换算实际距离还需要轮胎有效周长等数据。

绕行结束后保持末段速度，继续等待连续 3 帧新鲜有效普通路线，再恢复普通寻迹。各段通过编码器、陀螺仪与非阻塞状态机自动衔接，并设有故障与超时处理。路线数值属于当前配置，不应视为已经适配任意障碍物尺寸和摆放位置。

## 六、终点标记计数与停车

终点标记由横向排列的多条黑色短线组成。OpenMV 不逐条数出 8 条黑线，而是在已有灰度网格的底部小范围中检测分布式黑白特征，避免重复全图处理。检测结果复用原通信包的标志位传送给 H743。

主控仅在一次标记由无到有时计数，持续看到同一标记不会重复增加。标记消失须经过连续 3 帧确认，以减少单帧漏检造成的误判。

停车规则如下：

1. 第一次经过标记，计数加一，继续行驶。
2. 第二次经过标记，计数加一，继续行驶。
3. 第三次经过标记后，等待标记完全离开检测区域。
4. 确认离开后开始非阻塞计时，期间继续原有寻迹与速度控制。
5. 1000 ms 到期后停车并锁存，普通启动操作不能重新启动电机。

标记计数逻辑本身不会在第一次或第二次经过时主动发出减速命令。但标记对原路线识别的干扰仍可能间接引起减速；用户已反馈首次经过存在顿挫，此现象尚需结合运行数据定位，不能视为已解决。

## 七、通信、调试与保护

OpenMV 与 H743 使用现有视觉协议传输控制信息，复用有效性、序号和校验机制，避免将损坏、重复或过期数据作为正常路线使用。K230 的红色触发通过独立串口中断接收，不占用普通视觉控制协议。

无线调试以逐飞助手为使用入口，可查看轮速、转向和任务状态等诊断数据。参数修改受原有权限及范围约束，配置保存等操作要求停车。无线停止、PE7 停止和原有故障处理仍保留。

舵机中位为 1530 μs，软件输出上下限为 1100～2500 μs。该范围属于当前工程配置，不代表重新测定后的机械端点。

## 八、软件组织与参数位置

| 文件 | 作用 |
|---|---|
| `openmv/main.py` | 视觉主循环、路线控制结果组织与发送 |
| `openmv/config.py` | 图像、预瞄、标记 ROI 等视觉配置 |
| `openmv/fast_gray.py` | 灰度网格处理与轻量标记检测 |

| `Inc/gyro350_config.h` | 环岛档位轮速与目标角速度 |
| `Inc/gyro_ring.h`、`App/gyro_ring.c` | 环岛动作时序与非阻塞控制 |
| `App/wireless_settings.c` | 无线参数默认值，包括实际使用的出环角度门限 |
| `Inc/obstacle_bypass_config.h` | 绕障角度、轮转量、速度与阶段时限 |
| `App/obstacle_bypass.c` | 绕障状态推进与回归寻迹 |
| `App/commissioning.c` | 整车控制门控、终点计数、延时停车与保护 |

部分参数具有构建一致性检查，不能只修改一处同名数值。尤其应区分头文件中的后备默认值、档位编译值和运行时配置；例如本版出环采用 280°，不能把环岛头文件中的 340°后备常量误认为当前实际门限。

## 九、作品特点与验证边界

本作品将普通路线识别、特殊元素判断和车辆运动控制分工处理：视觉负责提供环境信息，主控负责动作调度，编码器和陀螺仪负责运动反馈。普通寻迹、环岛和绕障复用既有执行器控制，避免为各任务重复建立整套驱动。

终点检测复用灰度网格与现有通信包，运动任务使用非阻塞状态推进，尽量减少对主循环的干扰。不过，是否影响实际帧率需要在相同运行条件下测量，不能仅凭代码规模作保证。

最近保存的一次主控记录为 2026 年 11 月 14 日 01:00:08，接收 OpenMV 数据帧率为 87 帧/秒。这是一次记录中的接收帧率，不代表长期最低帧率，也不是当前实时测量。

“7.6终极版”已完成软件回归、实际交叉构建及配套文件校验。用户确认其为当前实车成绩最快的版本；具体完赛时间、长期可靠性以及首次经过终点的顿挫原因，仍需以实车记录补充。
