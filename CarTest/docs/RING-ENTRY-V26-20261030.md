# v26 ring-entry camera candidate

The right-ring diagnostic capture established two independent entry problems.
Observed island-side expansion had the opposite sign to the entry test, so
visible arc rows failed the existing support threshold. After confirmation,
the old route required near observations of the inner boundary although the
island boundary was still visible only farther ahead. Changing the state
counter alone cannot produce an admissible control route.

## Final behavior

Ring-side expansion removes common lateral translation and then measures
rightward expansion for a right ring and leftward expansion for a left ring.
Left/right identities, ordinary steering mapping and controller gains are
unchanged. Arc row/run/span, three-new-frame growth, peak reversal, topology,
calibration and ordinary-route counter-evidence keep their existing thresholds.

A real ENTER-to-INSIDE confirmation opens one entry-transition lease, bounded
by the existing four-second entry time. A current, calibrated far inner arc
and a current near outer boundary anchor a continuous transition through the
reference row. The bridge interpolates geometric centers and applies each
row's frozen calibrated width. Every bridge cell across the full width must
be known road; black/unknown cells, invalid width, missing anchors or bounds
fail closed. Interpolated rows honestly mark both boundaries inferred.
Standard near inner-boundary tracking ends the lease; it cannot restart from
an ordinary route, expired lease or another session.

The main converter requires a certificate tied to the current tracker result,
frame and target buffer. It separately rechecks fresh observed endpoint rows,
their coordinates, contiguous support and span. Mixed observed sides and
double-inferred rows are accepted only under that transition certificate.
Existing locked-side routes retain their original checks. The selected
reference is labeled interpolated rather than reported as an observed edge.
The v26 bundle requires ENTRY_TRANSITION_API_VERSION=1 to reject mixed modules.

Control UART and profile pairing are unchanged. Diagnostic admission reason
names append new values without changing the RNGD3 record layout. The startup
identity is CARTEST_H750_RING_ENTRY_V26_20261030; the small UART diagnostic
identity marker is 0x20261030 and does not verify a complete source package.

## Verification and limits

381 camera tests ran with zero failures/errors and three existing skips. One
additional ground replay is explicitly excluded because its private RAW input
is unavailable. Tests include mirrored transition geometry, masks, endpoint
support, calibration, lease/session lifetime, reference provenance and final
main-loop V3 output. Ordinary routes and false-ring recovery remain covered.
All 23 production modules passed armv7emsp MicroPython cross compilation.

Private captured key poses were additionally evaluated using original row
evidence and masks reconstructed from their raw grayscale images. The new
geometric transition passed the full corridor check and main admission and
produced rightward weighted errors. This is a counterfactual entry-state
geometry check: image sampling does not preserve every threshold-history
update and does not constitute full sensor replay, powered traversal or FPS.

Actual main-loop mirrored synthetic entry packets were checked with the
unmodified H743 parser/servo target mapping. This verifies software direction,
not the physical servo or ground behavior. H743 source/configuration and all
paired ELFs remain unchanged; no H743 reflash/reset or automatic motor start
is part of this change. The previously built fifteen configurations are not
rebuilt for a camera-only change.

The restored H750 native APP is unchanged, SHA256
c693f1ce035f8ff12796e2b21c21d347d5ef8aac7b4a78f6343a089ad45dc154.
Its native build provenance remains the frozen original v25 runtime reference;
the v26 Python candidate uses the same native API and buffer ABI.

v26 is a candidate pending RAM confirmation, powered left/right ground tests
and both preview-off and actual-IDE dynamic 60+ FPS acceptance. v25 stationary
IDE performance is not relabeled as v26 performance. Same-camera calibration
is preserved. The before-change source/configuration and eighteen ELF copies
are hashed and archived privately. Actual logs, images, calibration and RAM
probe artifacts remain outside public checkpoints.
