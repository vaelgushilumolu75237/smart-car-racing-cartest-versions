# 环岛1100ms、340°与红障12%版

基于上一版按用户要求修改，当前参数如下。

| 项目 | 当前值 |
|---|---|
| 环岛识别后回中直行 | 1530μs，1100ms |
| C原速入环/绕环外轮目标 | 2.178圈/秒，上一版1.980增加10% |
| 相机确认入环后累计净转角 | 340°，达到后进入回中出环 |
| K230识别尺寸 | 保持320×120，共38400像素 |
| 红色触发 | 严格大于12%，实际红色像素>4608；4608不触发，4609起触发 |
| 红色区域框 | 总红色像素≤4608蓝框，>4608绿框 |
| 左前斜行，第2段 | 保持左右轮平均前进1圈 |
| 第3段右转恢复初始朝向后 | 立即进入第5段右转驶回赛道，完全跳过第4段向前越障 |
| 右前斜行，第6段 | 左右轮平均前进1.5圈（1500千分之一圈） |

实际绕行顺序为1→2→3→5→6→7→路线确认，不会在第3/5段间输出第4段的直行目标。第4段参数槽保留供既有数据结构兼容，但不进入、不计时、不累计该段行程。

其他保持：入环/绕环舵机偏转系数1875‰、1530μs中位、1100～2500μs限位；原角速度目标不变；出环回中后300ms；普通道路和绕障速度不变。只有C原速环岛速度加10%，B=1.500、C+20%=2.376、C+30%=2.574、C+40%=2.772圈/秒不变。340°门限和1100ms应用于所有启用环岛的档位，A仍不进环岛。

红色仍全幅实际像素合计，连续事件只发送一次R，无额外触发条件。画框只作用于独立显示图，不污染检测。绕障优先级、故障保护及连续3帧普通路线确认机制未改。路线角度/距离仍为未实车标定的候选值。

## 安装

H743：人工烧录当前工作区Debug对应档位，或本包H743对应目录的CarTest.elf；六档均已真实构建。

K230：使用K230_RED内main.py、settings.py、red_detector.py，放入/sdcard/cartest-k230/。若上一版320×120已经安装，仅red_detector.py有本次运行逻辑变化。startup.py是根目录启动器源文件，已正常启动时无需改动入口。上传后人工重新上电才运行新文件。

OpenMV：本次未改，无需因本次参数更新而修改。

参数位置：Inc/gyro_ring.h、Inc/obstacle_bypass_config.h、App/obstacle_bypass.c、k230_red_obstacle/red_detector.py。Debug名称同步更新。

## 验证

软件测试验证4608/4609严格边界、蓝绿框、几何、连续触发、明确3→5跳转及无第4段、右前1.5圈、1100ms等待边界、340°门限、C原速2178毫圈/秒、原OpenMV/无线回归，以及六档ARM构建。详见validation/software-validation.json。本次没有自动上传相机、烧录或复位H743、启动电机；未宣称实车验证通过。
