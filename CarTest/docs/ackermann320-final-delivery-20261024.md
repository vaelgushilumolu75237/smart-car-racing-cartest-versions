# 320×120 与阿克曼协调版交付（2026-10-24）

本轮完成源码修改、宿主验证、交叉编译及相机RAM静态测试。没有改写相机存储，没有烧录、复位H743或启动电机。下一步需要操作者安装配对版本后做架空与落地验收。

## 实测帧率及适用范围

使用OPENMV4P/H743、OpenMV 5.0.0，实景静止直道；实际采集320×120，内部80×60、每格取全部4×2像素最小值。保留生产配置的7个中线点、3段边界显示、每30帧GC和完整边界检查。

| 测试条件 | 三个完整10秒窗口的新采集帧数 | 帧率 |
| --- | --- | --- |
| 正式协调包；关闭USB图像预览 | 608 / 608 / 608 | 60.8 / 60.8 / 60.8 |
| 基础对比包；关闭USB图像预览 | 608 / 608 / 608 | 60.8 / 60.8 / 60.8 |
| 生产配置；开启USB图像预览，带临时序号标记核验 | 350 / 347 / 347 | 35.0 / 34.7 / 34.7 |

这是板端新采集帧计数，不是`clock.fps()`，没有重复发送旧图充数。无预览测试的电脑状态轮询间隔为5ms。开启预览时，电脑中间两个10秒窗口读到的不同标记数均为347，与板端窗口相符；临时标记平均增加约58μs/帧，未写入生产程序。

协调包首个窗口采集到接收器写入平均12.450ms、P95分桶上界13ms、最大14.760ms；完整周期平均16.426ms、P95分桶上界19ms、最大36.748ms。全部窗口的相同统计保存在汇总JSON中；吞吐达到60帧不表示每一帧都低于16.67ms。

UART使用RAM接收器，反向RESET/KEEP每50ms模拟，确认`KEEP/FRESH`及52行宽度缓存。所有完整窗口均为有效路线、完整接收器写入、无写入错误。它验证真实传感器和完整处理链，**不代表物理UART发送或新H743接收已验收**。60帧目前只在上述关闭预览的静态直道条件达到；打开USB预览约35帧，弯道、单边恢复和运动场景尚未完成板端验收。

原始板端输出保留在本机`logs/camera-bench-20261023/`，不发布用户现场数据；公开的汇总及原始文件SHA-256见同目录文档旁的`ackermann320-static-evidence-20261024.json`。

## 两套版本必须配对

| 用途 | OpenMV上传目录 | H743 ELF |
| --- | --- | --- |
| 正式协调试验 | `deliverables/OpenMV_Ackermann320_20261022/coordinated/` | `deliverables/H743_Ackermann60_20261022/C_Coordinated/CarTest.elf` |
| 基础对比 | `deliverables/OpenMV_Ackermann320_20261022/geometry_perf_only/` | `deliverables/H743_Ackermann60_20261022/C_Baseline/CarTest.elf` |

两套均使用固定16字节V2视觉协议，不能混搭旧12字节V1固件。每套相机上传目录有19个运行`.py`及哈希清单；上传其中全部运行文件，相机和H743是两次独立安装。

基础对比包同样有位置PD和受约束预瞄（0.35、限幅100），速度预判关闭，H743保留65:35差速与120μs/20ms限速。它不是完全不变的旧相机基线。

协调包预瞄为0.45、限幅120；预判弯道后请求降速，较快轮目标从4.8向4.0转/秒用200ms下降，出弯用800ms恢复。后轮内外轮目标按已施加的受限舵机PWM、商家标称底盘几何估算，不追随尚未执行的目标瞬跳；模型转角不等于机械实测转角。协调包正常舵机限速160μs/20ms，启动仍保留慢限速。保护1100～2500μs、100%电机上限、2秒丢线截止、200ms丢线减速、三帧恢复及250ms通信故障停车保留。

图像行权重从中间向上下递减：峰值1000，端部164；核心区为裁剪后y=40～79，至少3个实测支持行且跨度2格，支持不足时按已有降级规则使用最近实测支持。环岛策略已移出生产路线，不新增坡道识别。
