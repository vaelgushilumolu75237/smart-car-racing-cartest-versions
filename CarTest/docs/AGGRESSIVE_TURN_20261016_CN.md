# 2026-10-16 单边连续段与快速转向试验版

本版相机标识为 `AGGRESSIVE_TURN_20261016`。相机程序和H743固件必须配套更新；本版不是实车过弯验收结论。

## 使用哪一份

H743使用 `build/DebugFollowTurn/CarTest.elf`，对应VS Code启动菜单“行驶3档 - 快速转向70%/30%（日志开启）”。本轮落地试验选这一项，不选速度PI试跑。相机上传 `deliverables/OpenMV_AggressiveTurn_20261016` 中全部20个顶层 `.py` 文件，覆盖同名文件；不要混用旧配置、旧模块或旧 `.mpy`。不需要清空整个相机磁盘，先保存用户文件；如果存在这些模块的旧同名 `.mpy`，移走以免加载旧模块。

正常运行舵机变化上限为120μs/20ms，左右电机分别为40‰/10ms，即每10ms最多变化4个百分点。启动和停车后恢复保留原慢爬升及首次完整PWM检查。直线50%/50%，最大转向目标70%/30%，1100～2500μs端点和现有增益保持。软件变化速度不等于舵机机械速度。

## 单边路线变化

单边扫描按近端向远端建立连续段。局部断行、离群点或歧义不再让整帧所有正常边界失效；使用选中段，避免将相邻赛道、不同分支混合平均。

单边最少5行、跨度6格、允许缺3行、历史锚点半径16格。可使用不覆盖旧参考行的近端短链，参考位置随实际支持行记录。左右单边可经连续两帧和重叠行中线差检查切换；没有重叠证据时不强行切换。仍要求真实边界、可行驶走廊和有效宽度缓存，推算点不更新实测宽度。

## 3秒丢线保持

只允许已经完成启动且电机已有输出的会话进入保持。保存最后被H743认可的有效偏差，舵机继续受限走向该偏差对应的目标；不是冻结尚未到位的脉宽。左右电机保持入口实际占空比，不重新计算差速或加速。

3000ms从最后可靠帧接收时间算起，零散有效帧不延长；连续三帧可靠路线恢复正常，超时关闭输出，恢复须重新通过启动保护。PE7再次按下、250ms无数据和UART/协议/硬故障优先停车。3秒保持不能判断前方已经换弯，也不能作为视觉修复验收。

## 日志导出

跑完先按PE7停车，保持H743通电，不按F5、不复位、不重新烧录。ST-Link可以跑完后再接；供电和接线变化不得使核心板复位。导出必须使用这次实际烧录固件对应的ELF。

```powershell
cd "D:\Codex\smart-car-racing-codex-handoff\smart-car-racing\firmware\vehicle\CarTest"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\tools\export_run_log.ps1" -Elf ".\build\DebugFollowTurn\CarTest.elf"
```

默认HOTPLUG共享连接，按1000、400、100kHz进行有限连接重试；探针序号固定后不改选设备，成功频率用于后续读取。多个探针时需明确指定 `-ProbeSN`。不执行复位、擦除、烧录、暂停或解除保护。

`Unable to get core ID / No STM32 target found` 表示尚未读到核心，不是CSV格式错误。本轮初次只读检查中，探针可枚举、参考电压3.27V，但三档频率均失败。用户检查并重插后，枚举到的探针序号改变，使用当前探针在请求1000kHz、实际950kHz下连通H743（ID 0x450），并读到与14号4:22后版匹配的IDLE日志头。工具未执行复位或启动电机，尚未实机导出非空CSV。脚本重试不能代替修复SWD线路或硬件连接，不能据通用报错断言需要Debug Authentication或解除保护。

17号复测时，同一探针曾再次读不到核心，用户再次重插后恢复。新脚本已在实机生成IDLE状态报告：日志开启、启动事件0、记录0，且能在读RAM之前拒绝不匹配ELF；连接间歇失败的硬件根因尚未确定。工具没有执行复位或启动电机，但不能据此排除插拔时的供电或复位变化。此验证针对板上旧固件，不代表新版已烧录。状态报告也会如实显示故障；当次旧固件读到UART故障，不能把“报告生成成功”当作车辆无故障。

真正成功的行驶导出应有 `run.csv`、解码元数据和通过CRC的RAM数据。IDLE状态输出状态报告，不伪造空CSV。状态读取失败不删除已经完整校验的行驶CSV，但要保留失败说明。

H743日志头和记录各64字节，V2保持时长使用50ms刻度，V1解码仍用20ms；实际保持期限按毫秒判断。最新无效帧中的零偏差不是保持偏差，分析应看最近一次保持入口快照。

## 相机诊断

默认开启128×32字节RAM环形记录，首次成功发送的有效帧变无效帧后冻结；图像处理和UART继续运行。冻结前覆盖旧记录，断电、复位或重新运行脚本会丢失记录。

采集前先稳定取景；若发车前已经冻结，应重新开始相机脚本。结束后先PE7停车，再在OpenMV IDE停止脚本但不复位解释器，REPL执行：

```python
steering_diag_dump()
single_edge_diag_dump()
```

分别保存两段完整BEGIN到END文本。`record_errors` 非零表示诊断不完整。单边详细诊断使用独立扩展输出，不改变32字节记录或12字节UART；离线分析的 `--camera-trace` 使用第一段 `STEERING_DIAG` 文本，单边扩展另存供拒绝原因核对。相机与H743时钟不能直接相减，必须按帧序号及各自回绕周期分析。

```powershell
python .\tools\analyze_steering_chain.py --camera-trace "D:\相机诊断.txt" --h743-csv "D:\本次日志\run.csv" --status "D:\本次状态\run-status.json" --out "D:\本次转向分析"
```

## 用户实测顺序

先架空验证PE7启停、舵机左右方向、差速镜像及丢线保持；随后落地直道、单弯、连续二连弯。保存同版本视频、相机诊断和完整H743记录。区分相机指令给晚、指令偏小、软件受限输出和机械执行；PWM不是机械角度测量。未经实车测试，不能宣称本版解决所有弯道。
