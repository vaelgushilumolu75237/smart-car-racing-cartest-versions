## 新相机已测能力

用户声明相机主控已更换为 H750，模组为 MT9V034。厂商固件仍报告 `OPENMV4P with STM32H743`；此字符串是固件构建名称，不能据此推翻实物更换，也不能证明两种板子的 Flash 布局相同。

- SDK 握手成功：固件5.0.1、MicroPython 1.28.0-64、480MHz。
- 传感器 ID 0x1324，实测图像320×120。
- 固件报告外部 DRAM 可用；GC 后 Python 空堆约4,325,456字节。该数值不是整板物理 RAM 或帧缓冲容量。
- 固件未提供旧自定义 `UART.write_fifo`，保留同步 UART 路径；未刷入旧 H743 相机固件。
- 初始核心板只读状态显示会话未启动、两侧输出为零；本轮未用软件启动电机。

原相机程序通过 RAM 临时执行35秒，关闭预览、关闭每秒调试文字，使用真实传感器与真实 UART。完整10秒窗口分别为630、627、626个新采集/处理帧及完整串口写入，路线全部有效，写入错误为零，即63.0、62.7、62.6帧/秒。最后不足10秒的窗口不用于达标判断。

此结果仅证明修改前程序在当前静止场景、SDK连接但不预览的条件下的吞吐。不能当作新环岛算法、真正断开USB、完整 UART 接收链路、运动场景或整圈验收。当前可见画面只包含左侧外边界和右侧局部岛边，不能验证完整入环/出环时序。

新增元素模块 SHA-256 `c8ff5e5d052cbcc410e341e2c62dcd88d787081fc20421f5b5af75aa879451ca` 已在该相机实际 RAM 执行合成烟测，输出 `PASS; device_viper=1; heap_free=4146672`。覆盖边界时序、冻结宽度、环内与出口补线、走廊暗洞拒绝、A档环岛关闭和十字专用采样核。这证明实际 MicroPython/Viper 路径能执行这些合成输入，不是对真实环岛画面的识别验收。

## 新通信约定

- 正向 V3 保持16字节，字节11为 profile_ack（0未知、1 A、2 B、3 C），其余位置和 CRC 范围沿用 V2。
- 反向 V1 RESET/KEEP 仍为8字节，不承担里程或配置职责。
- 反向 V2 profile-state 为20字节：A6 5A、版本2、类型2、独立序号u16、档位u8、会话标志u8、修订u16、会话令牌u32、平均正向轮转毫转数u32、CRC16。CRC覆盖前18字节，多字节字段小端。
- 档位确认必须新鲜且匹配；新三档不能靠旧确认启动。里程只辅助视觉状态，不单独决定进入、转向或退出。
- H743运行日志头和记录保持64字节。ACK1快照 V1/V2 均为64字节；解析工具继续支持旧版本。

## 验收边界

实现中的环岛出口逻辑属于待校准功能。教程仅提供讲解图和入口补线思路，没有完整出口源码。静态图、宿主合成、编译通过均不能证明完成规定环岛路线。

最终需按相同版本完成：架空启停与非空日志、落地直道、左右弯、十字、左右环岛、完整圈。各关键路线重复三次；新板完整算法在各场景每个连续10秒窗口至少60个新帧/秒。失败时依据同次视频与记录定位，不同时盲调速度和转向增益。
