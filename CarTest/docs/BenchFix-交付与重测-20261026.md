# 架空测试后修复与环岛重测

本轮只修复里程单位和停车后PI明细日志的冻结开销，不调整视觉路线、转向增益、轮速目标、差速比例或故障停车阈值。相机生产文件保持不变。

## 已确认的问题与修复

原里程换算使用每圈1,000,000单位，但反向通信和环岛辅助里程上限使用毫圈（每圈1,000单位）。现按每圈1,000单位转换，左右轮分别保留余数，只有一组有效样本整体通过才提交累计结果。60,000单位对应60圈。它仍是驱动轮转动里程，不是实际车身位移。

原PI明细日志在停车时同步扫描全部已保存记录计算CRC。此前一次架空记录在停车附近出现150ms间隔和loop_gap故障，该阻塞是与源码、时间戳相符的嫌疑，尚非板端计时证明。本轮将校验分为每次最多16条记录，主循环持续服务通信和保护。冻结途中禁止追加，保持首次停车时间，完成后才发布FROZEN及最终CRC。50ms主循环超时保护保留。

主日志头和记录仍各64字节；PI明细头64字节、记录48字节；UART格式不变。

## 实测顺序

1. 先架空驱动轮，相机对准明亮直道。核对B档配对、新鲜有效路线、无故障和零输出。用户按PE7启动约5秒，再按PE7停车。
2. 导出非空主日志和PI明细，检查版本、CRC、会话一致，确认停车后不再出现loop_gap。检查累计毫圈与同段编码器转数相符。软件测试通过不能代替这一步。
3. 通过后再落地测试普通直道和单弯，然后右环岛、左环岛。每次由用户手动启动和停车，不由工具启动车辆。
4. 环岛从入口前能看见本车道双边的直道起跑，先建立实测宽度与路线历史，避免从已经缺边的位置直接启动。保存同次视频、进出环岛时刻和H743记录。每个方向重复三次，普通弯道和十字另作对照。

## 性能与证据边界

此前明亮直道的H743接收窗口为66～69帧/秒。另一个失效场景轮廓补救路径只有约27.7帧/秒，仍需单独优化和板端复测，不能宣称所有场景均已达到60帧。当前修复不改变相机算法，也不能据此宣称左右环岛已通过实车验收。
