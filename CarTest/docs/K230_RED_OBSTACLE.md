# K230 红色障碍左侧绕行

本版基于当前 R24 工程修改。原 OpenMV 继续负责寻迹和环岛；新增的亚博 K230 只负责红色检测，不替换 OpenMV。未自动上传相机、烧录或复位 H743，也未启动电机。

## 红色触发

K230 固定采集 320×240 RGB565 图像，共 76800 像素。对全幅图像按 LAB 红色阈值分类，以单像素步长搜索所有连通区域，累加每个区域实际匹配的像素数，不使用外接矩形面积、最大色块或抽样估算。

实际红色像素 **严格大于 11520** 才发送单字节 `R`（十六进制 `52`，不带回车换行）。连续超限只发送一次；恢复到 ≤11520 后重新允许下一次事件。没有距离、形状、稳定帧数等附加触发条件。颜色分类阈值在 `k230_red_obstacle/settings.py` 的 `RED_LAB_THRESHOLD`，当前值为待现场确认的候选值。

K230 文件为 `k230_red_obstacle/main.py`、`settings.py`、`red_detector.py`，需放在相机可导入的同一目录并配置为启动入口。交付包中的 `.mpy` 仅作为编译证据，安装使用 `.py`。本次没有替你写入相机。

## UART 接线

| K230 | H743 | 说明 |
|---|---|---|
| GPIO9 / UART1 TX | PC11 / UART4 RX | 115200，8 数据位，无校验，1 停止位，3.3V TTL |
| GND | GND | 必须共地 |
| GPIO10 / UART1 RX | 不接 | 单向触发不需要回传线 |
| 不接 | PC10 / UART4 TX | 本版未启用发送 |

不要把 K230 TX 接到原 OpenMV 的 PA10，也不要接无线模块的 PA3。串口信号不接 5V。相机电源继续使用板卡指定的供电口；以上只列通信接线，不把串口引脚当作电源。

本工程检查未发现 PC10/PC11 被现有业务使用。PC11 的 UART4_RX / AF8 已按 STM32H743 官方数据手册核对；主板上对应排针位置仍须按实际丝印或原理图找 PC11，未假定排针序号。

原功能接线保持：OpenMV USART1 PA9/PA10，无线 USART2 PA2/PA3，IMU SPI2 PB12/13/14/15，编码器 PA1/PA0 和 PC7/PC6，舵机 PA8，PE7 启停。

## 非阻塞状态机

车辆已经启动且无故障时，UART4 中断接收 `R`，主循环立即接管已有寻迹会话。停车时收到的命令直接丢弃，不缓存为下次启动动作。绕行期间重复命令丢弃。原 PE7、通信超时、编码器和 IMU 故障停车仍有效。

| 状态 | 行为 | 完成依据 | 速度来源 |
|---|---|---|---|
| 1 LEFT_OUT | 左转朝赛道左侧 | IMU 到 +30°目标航向 | 当前档普通弯道速度 |
| 2 DIAGONAL_LEFT | 沿左前航向直行 | 编码器平均前进 2 圈 | 当前档直道速度 |
| 3 RIGHT_FORWARD | 右转朝原前方 | IMU 回到初始航向 | 当前档普通弯道速度 |
| 4 PASS_FORWARD | 向前越过障碍 | 编码器平均前进 3 圈 | 当前档直道速度 |
| 5 RIGHT_IN | 右转朝赛道 | IMU 到 −30°目标航向 | 当前档普通弯道速度 |
| 6 DIAGONAL_RIGHT | 沿右前航向直行 | 编码器平均前进 2 圈 | 当前档直道速度 |
| 7 LEFT_ALIGN | 左转恢复原方向 | IMU 回到初始航向 | 当前档普通弯道速度 |
| 8 REACQUIRE | 回中停车，确认正常路线 | 三个连续、新鲜、有效的 V4 普通路线帧 | 确认期间为 0 |

第 8 阶段确认后自动交还原普通寻迹，通过原舵机帧与电机启动斜坡恢复；不需要另发启动命令。尚未找到正常路线时保持停车，避免继续盲走。这里不修改普通寻迹原有的丢线恢复规则。

各段相对触发时的初始航向控制，转弯过冲不会累加成下一段的目标方向。正航向为原工程校正后的左转方向。直行段同时保持该段航向。电机仍使用原编码器 PI、阿克曼内外轮分配、输出限幅和斜坡；绕行只覆盖其速度和转向目标。绕行优先于环岛控制，未触发时原环岛逻辑不变。

## 可调参数与初值

集中在 `Inc/obstacle_bypass_config.h` 的 `car_obstacle_route_config`。每段依次为：转角（毫度）、平均车轮行程（千分之一圈）、外轮速度（千分之一圈/秒）、目标/上限角速度（毫度/秒）、超时（毫秒）。**距离不是毫米，也不是电机轴圈数**，使用原工程的车轮编码器换算。

上述 30°、2/3/2 圈是按你“先凭感觉写一套”的授权提供的候选值，未测量障碍物尺寸、车轮周长或转弯半径，不能保证沿示意绿色轨迹完成绕行。四次转角默认相等，修改后须保持最终净航向为零，否则配置校验拒绝执行。

转弯角速度候选 60°/秒，直行航向修正上限候选 30°/秒，航向比例系数 1500/1000。转弯段超时 8 秒，斜行段 6 秒，中间直行段 8 秒；超时停车，不按时间假定走完距离或转角。

| 档位 | 直道 / 斜行外轮目标（圈/秒） | 转向外轮目标（圈/秒） |
|---|---:|---:|
| A | 5.600 | 4.400 |
| B | 4.800 | 4.000 |
| C | 5.600 | 4.400 |
| C +20% | 6.720 | 5.280 |
| C +30% | 7.280 | 5.720 |
| C +40% | 7.840 | 6.160 |

这些速度直接引用当前档普通直道/弯道宏；无线现有轮速缩放仍对最终目标生效。绕行不套用环岛速度降低 25% 或环岛舵机增量。

## 修改文件

- 新增 `k230_red_obstacle/` 三个 Python 文件：检测、单次事件、独立相机入口。
- 新增 `Inc/obstacle_bypass.h`、`Inc/obstacle_bypass_config.h`、`App/obstacle_bypass.c`、`App/obstacle_authority.c`：参数、七段状态机与现有控制权限接入。
- 修改 `Src/main.c`：UART4 中断与有界单事件邮箱、读取原编码器行程、复用原轮速 PI 输出目标。
- 修改 `Inc/commissioning.h`、`App/commissioning.c`、`App/gyro350_authority.c`、`Inc/gyro350_config.h`：控制状态、故障处理和绕行优先级。
- 修改 `CMakeLists.txt`、`CMakePresets.json`：六个保留档位启用新功能；增加测试和交付工具支持。
- 原 `openmv` 相机源码未修改；不修改 `openmv_clipped_midpoint`。

ST-Link 可读诊断变量：`car_obstacle_phase`（0 空闲，1～7 路线，8 等待寻迹，9 故障）、`car_obstacle_error`、`car_obstacle_uart_received/errors/ignored`、`car_obstacle_distance_millirev`、`car_obstacle_heading_target_mdeg`。这些不需要新增上位机软件。

## 验证边界

软件测试命令：`python tests/obstacle/run.py --zig <zig.exe路径>`。测试红色阈值边界、分散小色块计数、事件重入，以及六档绕行顺序、航向、里程、超时、停止、IMU 故障和连续路线恢复。交付清单另外记录原功能回归及六档真实 ARM 构建。

软件通过不表示相机实机采集、UART 电气连接、红色阈值或赛道绕行已经通过。首次实车需要核对 IMU 左右方向、编码器车轮圈数和上述候选路线参数。
