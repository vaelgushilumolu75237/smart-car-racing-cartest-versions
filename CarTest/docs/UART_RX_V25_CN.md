# V25：修复H743高速相机串口接收溢出

本版只修改H743接收路径。相机继续使用已经安装的V24程序，GPIO9/10、相机通信2000000及逐飞无线115200保持配套。

## 已确认的原因

2026-11-10通过只读SWD核对，H743实际Flash的全部ELF加载区与V24配套固件一致，USART1分频正确、FIFO已开启。新增串口错误全部为ORE接收溢出，PE、FE、NE计数均为零。它解释了屏幕持续识线、主控却间歇收不到完整路线的现象；不能据此声称所有接线或赛道问题已经排除。

V24在64MHz、Debug O0配置下，每个接收字节经过通用回调、保护包装及队列函数。2000000波特率8N1的连续字节间隔为5微秒，只有320个CPU周期预算。

## 修补

- 仅优化USART1接收中断及其内联成功路径；共享FIFO服务算法与队列写入实现仍由主机测试直接执行。
- 每次中断最多处理16字节，每次读数据前检查硬件错误；错误/软件队列溢出仍立即撤销输出、清接收边界并按原规则恢复。
- 无线配置的软件接收环由256扩展至1024槽，为控制、诊断及图片分片突发留余量；其他配置保持256槽。
- 保留逐字节时间戳、内存屏障及短暂中断保护，不改电机、舵机、陀螺仪、350度规则和丢线恢复规则。
- Debug首项改为“Latest v25 | UART RX overrun fix / camera V24 2M | Wireless C +40%”。

## 安装与验证

1. 保持车辆停止，在当前工作区选上述Debug首项，烧录配套H743固件。也可使用本版安装包的H743/Wireless_Gyro350_C_Plus40/CarTest.elf。
2. 相机保留已安装V24；不必重新安装相机或修改逐飞无线115200设置。
3. 烧录后保持停止，用已有逐飞第4页核对相机RX持续增长、UART错误停止增长、路线序号持续更新，再检查第5页路线有效及故障清除。此项未完成前不宣称通信已恢复或整车达到60帧。

构建、主机回归和ARM反汇编检查见配套验证JSON。反汇编检查确认移除了接收成功路径的间接调用，但不是实机周期测量。本次没有自动烧录、复位H743、上传相机或启动电机；当前修补的实机接收帧率和赛道行为仍待安装后验证。
