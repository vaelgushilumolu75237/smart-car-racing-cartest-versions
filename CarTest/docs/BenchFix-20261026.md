# H750 bench follow-up firmware fixes

This change addresses two software issues found while reviewing the 2026-10-26
bench export:

- Session odometry wrote a value named millirevolutions but scaled count deltas
  by 1,000,000 per revolution. The production conversion now uses 1,000 and
  carries the fractional numerator between accepted samples, independently
  for each encoder. Both tentative carries are committed only after both sides
  and the cumulative sums pass validation. The value `60,000` therefore means
  60 turns, while repeated sub-revolution samples no longer lose fractional
  counts. See `App/session_odometry.c` and `Src/main.c`.
- Freezing the speed PI trace previously calculated the chronological CRC for
  the complete 2,048-record ring synchronously. Freeze now processes at most
  16 records (768 sample bytes) in each service call. Its first call captures
  the stop time and trace identity/order; appends are rejected while that
  snapshot is pending; the 64-byte header is marked FROZEN only after the full
  CRC is complete. Per-record cache cleaning remains in append, with barriers
  retained around the freeze reads and final header publication. The 64-byte
  header and 48-byte sample ABI is unchanged. See `App/speed_pi_trace.c` and
  `Inc/speed_pi_trace.h`.

The existing 50 ms loop-gap fault and PE7 stop/protection paths were not
changed. The previous bench export by itself does not establish the duration or
cause of its post-stop loop-gap fault. This software validation does not prove
the change's timing or behavior on the vehicle; no hardware was accessed for
this change.
