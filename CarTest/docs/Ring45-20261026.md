# 45 cm straight row-width calibration and ring observer

This change stores a camera-grid width map measured on a straight section that
is 450 mm wide. The 450 mm value identifies the physical setup; the tracker
uses the measured per-row widths in 80x60 grid cells. It does not convert the
map to a metric normal offset or use an inverse-perspective transform.

## Calibration setup

Run calibration with the car parked on a level floor and all four tires in
contact. Align the mounted camera with a straight, topology-clear road section
whose measured width is 450 mm. Use the final camera height and pitch for the
calibration. If either changes, collect a new map. Manually record the camera
image-center height above the floor here before starting the collection:

| Site record | Value |
| --- | --- |
| Measured straight width | 450 mm |
| Camera image-center height above floor | ______ mm |
| All four tires on level floor | ______ |
| Camera height/pitch final for this calibration | ______ |
| Calibration date and operator | ______ |

The calibration collector accepts only fresh selected bilateral road rows
with both-boundary flags set. The runtime must call it only while stationary
on a clear straight, before enabling the vehicle session. The collector also
checks frame-to-frame stability and rejects curved centerline fits. It gathers
64 stable frames, takes a median per row with at least 32 samples, and fills
only internal gaps of at most three rows. Unsupported rows remain invalid.

The file metadata locks sensor ID `0x1324`, image/crop `320x120` at
`(0,60)`, grid `80x60`, floor row `8`, and reference row `40`. A CRC protects
the geometry and row arrays. The runtime stores the private map at
`/flash/ring_width_45.json`. A missing file, CRC mismatch, geometry mismatch,
insufficient reference/near support, or failed three-frame startup width check
keeps B/C ring handling ineligible. A valid map needs at least 12 supported
rows spanning 20 rows, a valid row within three rows of reference row 40, and
five valid near rows (48..59) including a contiguous run of four.

## Ring evidence and route construction

Profile A keeps its existing ring-off behavior. Profiles B/C observe the
already extracted row arrays. They do not scan the image again or write the
ordinary width cache.

Entry requires a single-side loss or outward movement across mid/far rows
8..47, a stable opposite boundary, and a near anchor in rows 48..59. The
tracker confirms the initial event over two frames, then requires the real
inner boundary to reappear at least four grid cells outward and show a
three-cell peak reversal for two frames. Ambiguous topology aborts the
candidate. A candidate cannot steer before arc confirmation.

For a left ring, the tracker locks the observed left edge and computes the
right edge from that row's calibrated width. The right-ring path mirrors this.
Rows whose synthetic boundary would leave the field of view are omitted; the
remaining rows must still pass the known-road corridor and near-support gates.

For a left-ring exit, the tracker observes a drop and return of the real right
edge. The returned edge must form a contiguous fit of at least eight rows,
span at least 12 rows, and remain within two grid cells of the straight
reference. It must pass for three frames before the tracker can synthesize a
left edge from the real right edge and calibrated width. Reacquisition then
requires three genuine bilateral, aligned frames. The existing 2 s entry,
16 s active, and 60-revolution guards remain visual-state limits; odometry
alone never advances a ring state.

## Host API and evidence boundary

`RingWidthCalibration.accept_rows(rows, count, stride)` accepts packed rows
`[y, left_x, right_x, flags, ...]` in any order with unique row indices and
`(flags & 7) == 7`. Check
`collection_complete`, call `finalize()`, and save only when its `ready` field
is true. `load(path)` returns a not-ready object with a reason for absent or
invalid files. `TrackElementsTracker` defaults to
`require_calibration=True`; synthetic legacy fixtures must opt into
`require_calibration=False` explicitly. Startup validation uses
`observe_ring_calibration(rows, count, stride)` and reports its status in the
reusable `tracker.result` diagnostics.

Host tests establish row-map collection, metadata/CRC checks, gap behavior,
mirrored entry/exit, branch and S-curve rejection, and route-geometry guards.
They do not establish physical camera calibration or vehicle performance.
