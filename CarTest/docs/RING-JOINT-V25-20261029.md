Speed targets, gains, global steering direction,200ms loss ramp and2000ms vision-hold deadline are unchanged. No board flash/reset, camera upload or motor start was performed.

A currently accepted ordinary bilateral corridor, supported near-field and width-consistent within20% across at least8rows spanning12grid rows, vetoes entry in OBSERVE/ENTRY_CONFIRM/ENTER. Interruptions/session changes/rejections reset the counter; duplicate feedback in one frame never increments it. Recovery aborts to REACQUIRE, releases side/frozen-width state, clears target output and restores only the same frame's preserved valid ordinary selection. It never turns an unvalidated route into a valid command.

## Confirmed route-admission defect

The real calibrated target producer marks width provenance with TARGET_WIDTH_FROM_CALIBRATION=32. The old main-loop converter required TARGET_WIDTH_FROM_CACHE=16, so it rejected those calibrated targets. Tests previously used16 and missed the production mismatch. The converter now accepts exactly one recognized provenance and requires both ready calibration and parked checks for32. Production-required calibration cannot be satisfied by16, missing or combined provenance. Current-edge and reference-row checks still apply.

No global steering reversal or sign forced from ring-side labels was added. The side label is an observed boundary identity. Tests now pass mirrored calibrated geometry through actual main-loop V3 output, then the real C++ parser and extracted unchanged H743 follow_servo_target function. Example mirrored errors-443/+443 map to1397/1830us around1530us center. These are software target checks, not measured physical servo motion. The separate reported handheld inward/outward behavior lacks same-event ring/route/servo records and remains a physical validation item, not a claimed completed repair.
