# 第二弯候选衔接与丢线减速试验版

版本：`v20261018-second-turn`。软件交付，实车结果待测。

## 本轮范围

保留关闭预瞄、80/20位置权重、既有增益、120微秒/20毫秒舵机限速及最大70%/30%差速。只修改单边候选衔接、丢线轮速处理及诊断记录。

两侧单边候选都合格时，必须至少有5个共同实测行、跨度至少6格，每个共同行推算中线差不超过3格，左右边界顺序及原有可行驶区域检查均合格。沿用历史边界身份；没有历史时按支持行数、近端延伸选择。输出仍是单边推算，不向实测宽度缓存回灌。

丢线后继续朝最后可靠偏差对应的舵机目标转向，左右占空比从入口实际值在300毫秒内减至目标。目标高侧最多40%，低侧按比例且以30%为下限；任何一侧都不提高到入口值以上。例如70/30→40/30，50/50→40/40。3000毫秒截止从最后可靠帧接收时间算；零散有效帧不重置期限。三帧连续可靠路线恢复后通过原有限速逐步恢复。

- 相机：`deliverables/OpenMV_SecondTurn_20261018/`中的全部顶层Python运行文件，整体覆盖相机对应文件。
- 修改前恢复包：`deliverables/CarTest_PreSecondTurn_20261018_Restore.zip`，含源码、配置及16个原有ELF；同目录`.sha256`用于校验。
- 生产相机源码仍在`openmv/`。不维护对照版目录。

## 下一次验证顺序

先由用户手动完成架空检查。启动前确认日志IDLE，按PE7启动后ACTIVE，再按一次停车后FROZEN。保持H743供电，不复位、不重新烧录，使用Hot Plug导出。必须取得非空CSV，版本、CRC及诊断快照与日志头一致，才能进入落地测试。

随后分别测试直道、单独左弯、单独右弯，再以同一组连续二连弯重复三次。每次记录固件/相机版本、电池状态、是否出界、同次视频与H743日志。相机收到停车/重置通知后自动输出诊断，保存输出中的开始和结束标记及中间全部行。

验收需要首弯保持通过，连续二连弯三次均不出界、无硬故障，并能够从同次记录解释视觉输入、保持状态和输出。软件测试与编译不证明机械转角或实车通过率。失败10叠字视频仅作辅助定位，不作为准确的原始图像回放。

本轮不自动上传相机、烧录或复位H743，不启动电机。

## 导出命令

完成架空启动和停车后保持H743供电，不按F5、不复位。PowerShell执行：

```powershell
cd 'D:\Codex\smart-car-racing-codex-handoff\smart-car-racing\firmware\vehicle\CarTest'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\export_run_log.ps1 -Elf .\deliverables\H743_SecondTurn_20261018\DebugFollowTurn\CarTest.elf
```

必须使用与实际烧录固件配套的ELF。成功导出会打印CSV路径；IDLE只报告状态，不制造空CSV。若CSV已解码但独立诊断无法核对，工具保留证据并返回非零退出码，不算完成一次有效验收。

## 相机诊断限制

诊断缓冲保留首次有效转无效前最多64条及触发后最多192条。停车RESET通知到达相机后自动输出一次；需保持反向UART接线，并保存OpenMV终端完整输出。当前反向协议不能区分准备阶段KEEP和车辆实际行驶，因此停车取景也可能填充缓冲；对照帧序号、H743启动事件及同次视频分析。

交叉编译使用本机MicroPython v1.25.0工具、armv7emsp目标。编译成功不等于已在OpenMV v5.0.0固件运行验证。请整体替换相机目录中的20个运行文件，不混用旧的main.py/config.py/算法模块。
