## 保留的功能

- 新采集320×240灰度图的中心 `(0,60,320,120)` 区域，进入原有320×120算法。
- 每个4×2像素取最小值形成80×60网格，原阈值、边界、拓扑、单边恢复及轮廓规则保留。
- 普通路线位置PD、受限预瞄、速度请求和十字策略沿用；环内转向改由陀螺仪控制。
- 正向V4仍为16字节；反向RESET/KEEP V1/8字节和档位/会话V2/20字节
  增加陀螺仪能力与出环释放标志。V2/V3解析保留用于历史构建，陀螺仪档只接受V4配对。
- ACK、停车标定检查、当前帧证据、整包写入确认、超时和无效帧语义保留。
- 环岛记录保持有界RAM采集，原有停止冻结/保存时机保留；存储改到K230 TF卡目录。

移植脚本 `tools/port_k230_r24.py` 明确禁用ARM专用发射器和原生扩展，采用已有
参考实现。既替换导入，也更名编译器识别的装饰器，避免RISC-V上误编译Thumb汇编。
没有把H750固件、ARM原生`.mpy`或厂商固件镜像安装到K230。

## 亚博豪华版接口

厂商通信插座为UART1：TX=GPIO9，RX=GPIO10，115200/8N1。

| H743 | 亚博K230通信插座 |
| --- | --- |
| PA9 / USART1_TX | UART1_RX / GPIO10 |
| PA10 / USART1_RX | UART1_TX / GPIO9 |
| GND | GND |

插座另有5V供电脚，须按实物丝印辨认，不能按旧OpenMV P4/P5编号接线。
K230 `UART.STOPBITS_ONE` 数值为0；适配器使用命名常量，避免把旧`stop=1`误设为两位。
工厂固件没有OpenMV的timeout关键字，适配器不传入这些不支持的参数。
部分固件缺少`UART.any()`，采用最多256字节的二进制预读缓存，保留拆包和零字节。
Python层不将None或短写视为整包成功；实际驱动是否如实报告写入及H743物理接收需板上核验。

屏幕按厂商ST7701、640×480初始化，检测仍为320×120，不改变算法图像大小。
`k230_settings.py` 可选 `DISPLAY_MODE="lcd"`、`"ide"`或`"off"`。
LCD模式同时开启IDE输出，在屏幕中心显示检测图；没有新增触摸启停或替代PE7。
预览连接标志只表示已启用显示目标，不表示USB物理连接已测得。

## 安装和手动启动

安装包目录为 `Install/K230`。先保留K230现有TF卡程序与GUI，再将该目录全部文件
复制到K230 `/sdcard/cartest-k230/`。不要覆盖设备原来的 `/sdcard/main.py` 或GUI。
本次没有执行复制、刷固件或开机自启配置。

1. 用CanMV IDE打开该子目录的 `probe_k230.py` 并手动运行。它只采图和预览，
   不打开UART。终端显示固件、传感器枚举、裁剪形状和采图预览帧率；这不是算法FPS。
2. 核对镜像/翻转、相机安装和新视野，在实测45cm平直赛道上完成新的停车宽度标定。
   手动运行 `calibrate_k230.py`。沿用原r24要求：B/C档新鲜停车状态、轮转数不变、
   足够合格采集帧；该程序只发送无效V3且ACK0，不能用标定程序启动车辆。
3. 标定通过后，手动运行 `run_cartest.py`，检查档位确认、反向RESET/KEEP、
   路线有效性和结构化诊断。H743是否配套须以实际身份为准。

首次安装附带的 `ring_width_calibration.json` 是明确not-ready占位文件。
完成标定后原子写入真实格式3标定，包含实际K230传感器枚举和摄像头/安装几何绑定，
CRC覆盖绑定信息。换板、换摄像头、调整安装或改输入几何后必须重标；
`MOUNT_REVISION` 用于区分人工改变的安装几何。
缺标定或绑定不符时B/C保持原门控，不通过改标签、伪造传感器ID或硬设ACK放行。

运行数据默认位于 `/sdcard/cartest-k230/`，应先备份再升级该目录。
公共检查点不附真实标定和采集数据；恢复公开源码需重新标定或恢复适配私有标定。

## 平台差异和验收边界

K230镜头、曝光及视场与H750/MT9V034不同，320×120尺寸相同不代表几何标定相同。
部分CanMV版本的曝光/增益接口是空实现，因此本版使用固件ISP默认曝光，
明确不宣称已施加OpenMV的10ms曝光上限或12dB固定增益。运动模糊和阈值效果待实测。

当前可移植参考实现没有ARM汇编或自定义原生预览加速，不承诺60FPS。
未放宽200ms处理预算，也没有跳检测、减小网格或将旧帧重复发送为有效帧。
在目标固件确认后，应分别测算法新帧率、实际IDE新画面率、有效率、内存和串口时序。
若低于要求，依据板端剖析选择K230支持的C/RVV或ulab优化，保留参考实现作等价对照。

原r24本身未通过完整地面环岛；本版350°和固定直行出环策略仍待实车调整。
普通直道、左右弯、十字、左右环岛、物理转向与整圈验收分别记录。

## 软件验证

运行 `python tools/test_k230_port.py` 验证原r24算法。
三项旧OpenMV安装包/平台AST冻结检查明确排除，原因写入报告，未算通过；
其余跳过项同样保留。`tests/k230_port` 验证平台接口、帧新鲜度及标定隔离。
MicroPython1.28编译只生成无原生代码的可移植字节码用于检查；安装交付使用`.py`，
避免假定设备的MicroPython字节码版本。完整证据摘要为 `K230_VALIDATION.json`。
