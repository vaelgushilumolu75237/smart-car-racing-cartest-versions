# K230 / H743 / ICM42688：350°环岛候选版本

版本：`CARTEST_K230_GYRO350_20261106`；主控预设：`DebugGyro350Speed140`。
用户已确认的控制方案在本版实现。软件检查不能证明环岛出口对齐、半径合适或赛道通过。
本次未上传相机程序，未烧录或复位 H743，未启动电机。

## 已实现的顺序

1. 上电静止约2秒校准。编码器静止、电机关闭且非运行会话时才允许收集；
   三轴角速度、重力模长和加速度变化符合阈值才连续累计，晃动重来。
   未完成校准、数据过期或陀螺仪故障时不能启动此档。
2. PE7按原启停流程启动，反向RESET/KEEP、会话令牌、相机标定和ACK门控保留。
   连续3帧普通道路后才允许环岛接管，不能由环岛信号直接启动车辆。
3. K230跟踪器确认ENTER后发送方向；H743按左右镜像的固定目标角速度控制入环。
   候选目标为左转+120°/s、右转−120°/s。归一化道路误差正值为右，控制器内部作符号转换。
4. K230当前INSIDE、ring_confirmed、target_valid、非entry_transition且连续3个相邻帧，
   通过标定和本帧处理预算检查后发入环确认。H743收到该事件时记录本次yaw原点。
   开始入环时的转角不会算进350°。
5. 环内按陀螺仪角速度PI调舵，不使用视觉边界纠偏。外轮目标7392 milli-rps
   即7.392转/秒；内轮按当前软件舵角的阿克曼模型缩减。轮速PI、编码器保护和输出限幅保留。
   当前模型的轴距、轮距和转角沿用旧工程参数，尚未测量确认。
6. 本次绕环方向的净进度达到350000毫度时进入回中。反向摆动抵扣进度，
   不对每步转角取绝对值求和。达到门限并不保证车头对准真实出口。
7. 实际软件输出PWM到1530µs且完整舵机帧已就绪后，保持回中300ms，
   目标轮速暂保留7.392转/秒。软件PWM达到中位不表示机械舵机已实测回中。
   回中开始即通过反向标志释放K230旧环岛状态，恢复普通路线观察；不等待出口视觉。
8. 300ms结束，若有连续3个新鲜普通路线帧则交还循迹；否则进入SEARCH，
   从此时起最多再续行3000ms，保持回中，按原300ms过程把实际占空比减至旧丢线低速输出。
   这里保留的是原占空比减速策略，SEARCH不再闭环跟踪7.392转/秒。
   无效帧不能重置期限，合格路线可提前交还；到期撤销电机输出，等待3帧普通路线，
   再通过原零输出启动门控恢复。相机通信持续是续行前提。
9. 入环4秒、绕环16秒、回中1秒各有独立超时。相机通信超时250ms、
   ACK失配、陀螺仪异常/过期、编码器故障和PE7停止会撤销输出。
   停车后旧环岛状态和角度会话清除，不能靠旧帧重启。

若主控复位、通信异常恢复或缺少本次ENTRY时直接收到INSIDE，不能转成旧视觉环岛控制；
陀螺仪未接管时只允许当前有效普通路线提供行驶授权。

## SPI候选接线

ICM平放，Z轴垂直地面。模块裸芯片只支持低压供电，实际模块是否带稳压器需要核对实物；
信号按3.3V逻辑使用，不能把5V直接接到不带稳压的裸芯片。

| H743候选引脚 | ICM42688模块信号 |
| --- | --- |
| PB13 / SPI2_SCK | SCK / SCL |
| PB14 / SPI2_MISO | SDO / AD0 |
| PB15 / SPI2_MOSI | SDI / SDA |
| PB12 / GPIO | CS，低有效 |
| GND | GND |
| 经模块规格确认的电源 | VCC / VDD |

本工程没有其他已配置外设占用这四个PB引脚，但尚未证明车上主板排针已引出且空闲。
STC参考工程引脚不等于H743接线。INT脚本版不用，主循环轮询数据就绪。
v8 使用原 SPI2 接口这组引脚进行 GPIO 四线 SPI Mode 0 收发。
经核对的 HCLK=64MHz，DWT 计时半周期不少于 2μs，SCK 不高于 250kHz。
每次最多 17 字节；超过 1ms 预算后检测退出，CS 拉高、SCK 拉低；中断保持开启。
DWT 不运行、主频不匹配、总线超时均返回失败，沿用原故障停车门控。
GPIO传输不关闭中断；若被中断抢占，恢复执行后检测期限，超时则释放CS并返回失败。

驱动依据本地ICM-42688-P手册DS-000347 rev1.2：WHO_AM_I=0x47，
INT_STATUS(0x2D)的DATA_RDY_INT为bit3(0x08)，200Hz、±2000°/s、±16g。
只有新数据才更新采样时间和积分；使用实际采样间隔，零偏从原始量均值校正，
不复制参考STC例程中的二次除量程系数或固定时间步。采样间隔大于25ms触发故障，
50ms无新数据触发陈旧故障。没有磁力计，只做相对航向积分，仍存在漂移。

## 参数与诊断

`Inc/gyro_ring.h`：120000 mdps、350000 mdeg、7392 milli-rps、300/3000ms
及各阶段超时。`App/gyro_ring.c`：角速度前馈250、Kp=2归一化单位/(°/s)、
Ki=1归一化单位/°、积分限幅250；都是待实车调节的软件初值。
`Inc/icm42688.h` 的 `CAR_IMU_YAW_SIGN` 用于安装正负号；角速度与积分角同时镜像。
逆时针车身转动应得到正角速度，实物方向核对后再运行。

LiveWatch：`car_imu_ready`、`car_imu_fault`、`car_imu_sample_count`、
`car_imu_z_mdps`、`car_imu_bias_raw_q16`、`car_imu_yaw_mdeg`、
`car_gyro_phase`、`car_gyro_fault`、`car_gyro_progress_mdeg`、
`car_gyro_control_error`、`car_gyro_search_elapsed_ms`。
阶段0=OFF、1=ENTRY、2=ORBIT、3=CENTER、4=EXIT_STRAIGHT、5=SEARCH、
6=WAIT_ROUTE、7=REARM、8=FAULT。运行状态与物理输出分别看；
旧视觉诊断字段仍只描述视觉，不能凭vision_valid=0断言陀螺仪控制已停。
IMU故障位：1=BUS、2=WHOAMI、4=STALE、8=DT、16=CONFIG。
环岛故障位：1=IMU、2=TRANSPORT、4=TIMEOUT、8=INPUT。

## 通信扩展

正向仍16字节，CRC16覆盖bytes2..13。V4的byte10：bits0..1原弯道阶段、
bits2..3环岛阶段(0无/1入环/2已入环)、bits4..5方向(0无/1左/2右)、
bit6普通道路有效、bit7保留0。方向与阶段须配对，普通道路标志不能与无效帧并存。
byte11仍ACK，必须为3。车道有效位不承载环岛识别含义。
反向profile-state的flags增加0x04=主控陀螺仪能力、0x08=释放旧环岛；
保留原0x01/0x02语义。只有新鲜、同档位、同会话状态才允许使用。

## 构建与检查

在本工程目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1 -Preset DebugGyro350Speed140 -Fresh
```

完整检查入口为 `tools/verify_k230_port.py`，需要指定真实 `--mpy-cross` 和 `--zig`。
`tools/test_k230_port.py` 对旧算法回归显式关闭GYRO350_REQUIRED以隔离原算法合同；
新增 `tests/k230_gyro` 使用本版默认要求配对，不能用旧526项替代新增协议验证。
驱动/状态机、主控整链路、实际main输出函数、HAL适配和相机算法分别验证。
所有声明的19个预设生成真实ELF，结果和哈希记录在 `K230_VALIDATION.json`。
MicroPython交叉编译只证明源码可编译成可移植字节码，不证明目标设备固件或FPS兼容。

本版固定120°/s与7.392转/秒决定实际绕环轨迹，缺少轮胎有效周长、舵机/轮胎响应
和赛道半径实测，不能宣称已匹配半径。首次手动安装前应核对主板引脚、模块供电、
转向符号和编码器方向；普通左右弯与左右环岛分别验收。真实路测数据留在私有目录。
