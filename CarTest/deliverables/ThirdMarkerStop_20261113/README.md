# 第三次黑色标记离开后继续寻迹1秒并锁定停车

基于现有 OpenMV/H743 六档工程增量实现；不改寻迹、环岛、K230红色绕障的算法、参数和优先级。

## OpenMV

复用 `FastGrayMasks` 每帧已经生成的80×60灰度缓存和底部区块Otsu阈值；阈值缺失时使用原有 `LEGACY_BLACK_THRESHOLD=55`。检测ROI由 `openmv/config.py` 的 `BLACK_MARKER_GRID_ROI=(12,48,56,12)` 指定，对应320×120画面中的x=48..271、y=96..119。

Viper函数最多检查672个已有网格值，不另采集图像、不再缩放/二值化、不扫描原图、不搜索轮廓。沿横向四个小区间检查黑白混合且横跨ROI的纹理，识别用户示例中的一组并排黑色短线，不逐条计数。普通单/双侧边界、纯白、全黑和实心横条不满足该纹理。ROI及判据仍需安装视角、赛道与光照实测确认；用户示例图只确认形态，不能替代OpenMV实拍验证。

复用16字节V4控制包的flags：0x04表示本帧标记检测完成，0x08表示存在标记。现有valid、环岛字段、包长和发送频率不变。0x08不能单独出现，CRC覆盖新状态位。V2/V3继续拒绝这些扩展位。图像处理未完成时不报告“已消失”；路线无效但标记检测成功时仍可报告标记，避免黑色标记遮挡边界造成漏计。

## H743

仅在已启动的寻迹会话中处理通过CRC、档位握手、时效及递增序号检查的V4标记状态。连续存在帧只计一次；至少连续3个新鲜、连续序号的“已检测且不存在”帧，才确认本次标记离开。单帧漏检、未知状态以及丢帧不会把一次经过分成两次。正常停止、收线恢复和无线重连不重置经过次数。

前两次经过不改变行驶控制。第三次离开确认时记下毫秒时间，在原控制周期内用无符号时间差非阻塞计满1000ms；期间不覆盖寻迹舵角、速度，也不放宽任何安全保护。更早发生原有安全停车时仍按原逻辑停止。

到期复用现有电机撤权/停车及故障锁存通路，增加专用原因 `CAR_FAULT_FINISH_MARKER`。计数上限为3；终点锁存后，本地启停、无线启动、重新找到路线、相机重启确认和故障确认均不能恢复电机输出，也不能启动无线电机测试。本轮停车保持至主控断电或复位重新初始化，不写Flash，不提供命令清除此锁存。

新增5个单字节状态和1个32位时间戳（含对齐约12字节）。不使用HAL_Delay，不增加独立任务。

## 修改与验证

功能源码：`openmv/config.py`、`openmv/fast_gray.py`、`openmv/main.py`、`openmv/vision_protocol.py`、`Inc/vision_protocol.h`、`App/vision_protocol.cpp`、`Inc/commissioning.h`、`App/commissioning.c`。

测试：`openmv/tests/test_black_marker.py`、`openmv/tests/test_steering_diag.py`、`tests/marker_stop/test_marker.c`、`tests/marker_stop/run.py`。冻结测试只允许新增ROI配置，继续检查原寻迹设置和算法未变。覆盖合成纹理、V4编解码及CRC、无效路线、重复帧/漏检/未知状态、三次计数、1000ms边界、毫秒回绕和终点后拒绝重启，并执行原环岛、绕障、无线回归与六档ARM实际构建。`tools/runtime_log_export.py` 同步补充终点停车原因名称，供已有日志读取使用。

不设置新的帧率限制；额外成本是有界Viper小区域读取、原包增加两位状态和主控常数时间比较。没有本次OpenMV实机前后对比，因此不能承诺实际帧率完全不下降。未自动上传相机、烧录/复位主控或启动电机。
